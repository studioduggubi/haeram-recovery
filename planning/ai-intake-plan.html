방문자의 이야기를,
사무실의 다음 업무로.

선택한 운영 방식: 관리자 화면 + 이메일 알림. 대화로 상담 준비 내용을 정리하고, 방문자가 확인한 요약을 사무실이 이어받는 구조입니다. 이 문서는 실행 기획안이며, 현재 홈페이지의 네 가지 질문은 AI나 자동 접수 기능이 아닙니다.

대화로 정리→내 요약 확인·수정→연락처·전송 동의→관리자 접수→이메일 알림

방문자가 경험할 흐름

화면·문구 예시 / 가상 대화
안녕하세요. 해람의 AI 상담 준비 도우미예요. 지금 가장 걱정되는 이야기부터 알려주세요. 제도 선택은 아직 안 하셔도 괜찮아요.
빚이 줄지 않는데 수입도 일정하지 않아요.
매달 부담이 크셨겠어요. 최근에도 수입이 들어오고 있는지부터 살펴볼까요? 정확한 금액은 몰라도 괜찮아요.
일은 하고 있는데 금액이 매번 달라요.
‘수입은 있으나 일정하지 않음’으로 정리했어요. 법원에서 받은 문서나 곧 다가오는 기한도 있나요?

한 번에 한 가지 질문

관심 절차 → 수입 형태 → 대략적 채무·재산 범위 → 부양·생계 부담 → 법원 문서·기한 → 선호 연락 방법. 자유 대화에서 이미 답한 내용은 다시 묻지 않습니다.

완료 전 본인이 확인

‘내가 말한 내용 / 아직 모르는 내용 / 상담 때 확인할 질문’으로 요약합니다. AI 추정은 사실과 분리하고 사용자가 고칠 수 있게 합니다.

상담 선택은 열어두기

‘꼭 해람과 함께하지 않으셔도 괜찮아요. 이 메모를 어느 상담에서든 활용하세요.’ 복사·다운로드는 접수 여부와 무관하게 제공합니다.

사무실은 목록에서 바로 다음 행동으로

아래는 가상 자료를 사용한 화면 구성안입니다. 실제 접수·저장·전송 기능은 아직 연결하지 않았습니다.

접수 상세 화면

사용자 확인 요약, 원래 발언 근거, 빠진 정보, 문서·기한 표시, 선호 연락 시간, 동의 이력, 담당자, 내부 메모, 다음 연락일, 상태 변경 이력을 함께 보여줍니다. 접수 상태는 새 접수 → 확인 중 → 연락 예정 → 상담 완료 → 자료 대기 / 진행 협의 / 종료로 관리합니다. AI가 신청 자격·수임 여부·예상 면책 결과를 결정하지 않습니다.

이메일은 알림, 상세 정보는 관리자 화면에서

제목: [해람] 새 상담 준비 접수 H-001

새 상담 요청이 접수되었습니다.
접수 시각: YYYY-MM-DD HH:mm
확인 표시: 문서·기한 언급 있음

관리자 화면에서 확인하기 →

세부 채무, 대화 전문, 연락처를 이메일에 싣지 않습니다. 링크만으로 열람되지 않으며 관리자 로그인이 필요합니다.

DB 접수 성공 후 알림 작업을 큐에 넣습니다. 이메일 발송 실패가 접수 실패로 보이지 않게 분리하고, 재시도 횟수와 오류를 관리자가 확인합니다.

중복 클릭은 같은 접수 ID로 처리합니다. ‘전송 중 / 접수 완료 / 접수 실패’를 분명히 보여주고, 접수 실패 시 메모 복사와 전화·카카오톡 연결을 유지합니다.

사무실 수신 이메일 주소와 발신 도메인은 운영 연결 전에 확정할 설정값입니다.

권장 구현 구조

영역설계
현재 사이트GitHub Pages 랜딩은 유지. 정적 메모 기능을 실제 AI 도우미로 전환할 때 백엔드 API를 연결.
서버 API서버리스 API 또는 기존 서버. AI 키·이메일 키는 서버 환경 변수에만 보관. 요청량 제한, 세션 만료, 입력 길이 제한, 허용 도메인·CSRF 정책 적용.
DB·인증PostgreSQL + 관리자 인증. 구현 후보 Supabase의 Auth·RLS·MFA를 사용하되 실제 제공 리전, 위탁·국외이전 조건은 도입 시 확인. 관리자 권한·담당자 열람 범위를 DB 정책으로 제한.
AI 계층공급자 교체 가능한 서버 어댑터. 법무사가 검수한 설명·질문 범위에서 응답. 요약은 정해진 JSON 스키마로 검증하고 사실·추정·미확인 정보를 구분. 모델은 한국어 요약·거절·비용 평가 후 선정.
알림이메일 전송 서비스 + 재시도 큐. 후보 Resend는 소유 도메인 확인이 필요하므로 사무실 도메인 DNS 연결 후 사용. 제목·본문에는 최소 정보만 포함.
자료 첨부1차 출시에서는 제외. 이후 로그인·접근 제한 저장소, 파일 검사·가림 처리·만료 정책을 갖춘 별도 흐름으로 추가.

정보 취급과 답변 원칙

  • 대화 시작 전 AI 도우미·서버 전송 여부와 처리 목적을 알립니다. 연락처와 사무실 전달 동의는 접수 단계에서 분리합니다. 운영 데이터 흐름에 맞는 처리방침·위탁·국외이전 고지는 도입 공급자 확정 후 검토합니다.
  • 초기 대화에서는 주민등록번호·계좌번호·신분증·금융 원본을 요구하지 않습니다. 사용자가 적더라도 서버에서 필요한 범위를 넘어선 식별정보를 가리고 외부 AI 전송을 제한합니다.
  • ‘가능 / 불가능 / 반드시 면책 / 탕감률’ 같은 확정 판단을 하지 않습니다. 모르는 내용은 모른다고 하고, 법무사가 확인할 질문으로 남깁니다. 긴급 기한·압류 언급은 사람이 우선 확인할 표식으로만 사용합니다.
  • 등록되지 않은 사무실·도구로 자료를 보내라는 대화 지시는 실행하지 않습니다. AI에 이메일 발송·수임 승인 권한을 주지 않고, 서버의 고정된 사무실 수신 설정만 사용합니다.
  • 보관 기간 초안: 미접수 대화는 짧은 만료, 접수 자료는 사무실의 업무상 필요와 관련 법적 의무에 맞춘 기한을 별도 확정합니다. 삭제·정정 요청, 권한 회수, 접근 이력, 복구 절차를 운영 화면에 포함합니다.

개인정보보호위원회는 생성형 AI 생애주기별 법적 고려 사항과 안전조치 기준을 제시합니다. 위 항목은 그 방향을 이 서비스에 적용한 설계 제안이며, 보관 기간·동의 문안이 확정된 법률 검토 결과는 아닙니다.

출시 순서와 완료 기준

  1. 대화·요약 검증: 현재 메모 기능을 기준으로 대화 화면과 사용자 수정 요약 구현. 가상 상황으로 질문 중복·근거 없는 추정·강요하는 문구 검수.
  2. 접수·관리 구현: DB·인증·담당자·상태·후속 연락·이메일 큐 연결. 사무실 수신 주소, 관리자 계정 목록, 발신 도메인, 공급자 계약·개인정보 문구 확정.
  3. 운영 전 점검: 무소득·불규칙 소득·법원 기한·자료 없음 등 20개 이상 가상 시나리오로 요약 누락과 법적 단정 0건 확인. 잘못된 타인 접수 열람 차단, 중복 접수 방지, 이메일 실패 재시도, 삭제·권한 회수 검증.
  4. 소규모 운영: 법무사 검수 후 공개. 접수 완료율·요약 수정률·첫 연락까지의 시간·알림 실패율을 측정. 실제 고객의 대화 전문을 분석 도구에 자동 전송하지 않음.

현재 상태: 프런트엔드 메모 개선과 운영 설계까지. 실제 AI 응답, 개인정보 접수 DB, 이메일 알림은 미연결입니다. 계정·서버 설정 없이 접수 완료처럼 보이는 화면은 공개하지 않습니다.
